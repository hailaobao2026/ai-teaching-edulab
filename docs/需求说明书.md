## 1. 文档目的

本文档描述 EduLab 交互教学课件平台的业务目标、用户角色、功能需求、非功能需求与验收边界，作为产品、研发、测试的统一需求基线。

---

## 2. 项目背景与目标

### 2.1 背景

平台将 `@wy51ai/edulab` 三大教学技能封装为 Web 管理系统：

- 立体几何（`edu-solid-geometry`）
- 解析几何（`edu-analytic-geometry`）
- 化学反应（`edu-chem-reaction`）

用户可通过浏览器提交参数，由服务端调度 Python worker 计算并渲染**自包含单页 HTML 课件**。

### 2.2 首期 AI 扩展目标

在固定题型之上引入 LLM，使**教师与学生**均可通过：

1. **文本**
2. **方程/式子**
3. **图片（识别 → 确认 → 生成）**

动态生成化学与数学（优先解析几何）交互课件。

核心原则：

- **LLM 只输出结构化 Spec JSON**
- **技能 kernel / schema 校验后才渲染**
- **API Key 仅服务端持有**
- **图片路径必须先确认再生成**

## 3. 用户角色与权限

| 角色 | 标识 | 主要权限 |
|------|------|----------|
| 学生 | `student` | 注册登录、固定题型生成、AI 生成（默认日配额 10）、管理自己的任务/课件 |
| 教师 | `teacher` | 学生权限 + 更高配额（默认 50）+ AI 健康检查 |
| 管理员 | `admin` | 全量管理：用户、配置、审核、统计、题型目录启停 |

默认允许使用 AI 的角色：`student,teacher,admin`（可配置）。

## 5. 非功能需求

| ID | 类别 | 要求 |
|----|------|------|
| NFR-01 | 安全 | sub2api Key 不下发前端；会话鉴权；角色鉴权 |

| NFR-04 | 性能 | worker 并发可配；单 job 长超时（模型推理可达 180–300s） |

| NFR-06 | 兼容 | 产出课件为自包含 HTML，可离线打开 |
| NFR-07 | 限流 | 注册/登录/AI 接口分级 rate limit |

## 6. 输入输出约定

### 6.1 AI 文本/方程

请求要点：

```json
{
  "inputMode": "text|equation",
  "content": "用户题干或方程",
  "skillHint": "edu-chem-reaction|edu-analytic-geometry|edu-solid-geometry",
  "idempotencyKey": "可选",
  "options": { "title": "可选标题" }
}
```

### 6.2 图片草稿

- 输入：`imageBase64` / `imageUrl` + 可选 `skillHint`/`note`
- 输出：草稿 `editable{problemText,equation,conditions,ask,skillId}` + confidence + warnings
- 确认后：生成 `kind=ai, inputMode=image` 的 job

### 6.3 课件产物

- 单文件 HTML（化学 Three.js+KaTeX；解几 Canvas+KaTeX；立几 Three.js+MathJax）
- 元数据：skillId、problemType、title、fileSize、publishStatus、visibility

## 7. 业务规则

1. **配额计数点**：成功创建 AI job（文本/方程 POST，或图片 confirm）时 +1。
2. **图片草稿不计生成配额**（可另做 draft 频控）。
3. **已知题快路径**优先于 LLM，降低成本与不确定性。
4. **分子扩展**：仅在校验发现缺 species 时触发；自检通过后才持久化。
5. **修复重试**：默认最多 3 次（`AI_MAX_REPAIR_ATTEMPTS`）。
6. **危险化学**：教学演示提示，不鼓励真实实验（后续可加强）。

## 9. 验收标准（首期）

1. 学生/教师可注册登录并查看配额。
2. 固定题型三学科均可生成 HTML。
3. 化学：已知反应 + LLM 动态反应均可出课。
4. 缺分子反应（如 `S+O2→SO2`）可自动扩展并渲染。
5. 解析几何：已知题 + LLM 动态题均可出课。
6. 图片：识别草稿可编辑，确认后生成课件；未确认不扣配额外的生成。
7. 无前端暴露 API Key。
8. 关键自动化测试（m0/m1/m2/m3）通过。

---

## 10. 约束与假设

- 上游模型通道为 **OpenAI 兼容 sub2api**。
- 依赖 Python 环境可 import `sympy`（解几/立几）。
- 不修改 `node_modules` 内 skill 源码作为长期方案；扩展通过 JSON/旁路注入。
- 模型可用性会变化，生产需可配置 model 与 fallback。
