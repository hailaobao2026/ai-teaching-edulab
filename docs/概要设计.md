## 1. 设计目标

1. 将 edulab 三技能产品化为可登录、可排队、可管理的 Web 系统。  
2. 在不破坏 kernel 正确性门闩的前提下引入 LLM 动态扩展。  
3. 前后端分离：React 前端 + Node/Express API + Python Worker。  
4. 支持开发态 Memory JSON 与生产态 MySQL。  
5. 密钥与模型调用全部服务端化。

## 3. 逻辑架构

### 3.1 分层

| 层 | 职责 | 主要目录 |
|----|------|----------|
| 表现层 | 登录、生成中心、任务、课件、管理 | `App.tsx` / `dist` |
| 接入层 | HTTP API、鉴权、限流 | `server/index.js` |
| 领域服务层 | 配额、AI 管线、技能目录、RBAC | `server/services/**` |
| 基础设施层 | DB、文件产物、LLM 客户端 | `server/db.js`、`uploads/`、`llm/` |
| 计算渲染层 | sympy/kernel/template | `@wy51ai/edulab/skills/**` + `ai/python/*` |

### 3.2 关键模块

| 模块 | 说明 |
|------|------|
| Auth/RBAC | 注册登录、角色、会话 |
| Catalog | 固定题型与启停 |
| Job Queue | 固定/AI 任务排队与租约 |
| Worker | 拉取任务、调用 skill/AI 管线、落 HTML |
| Lesson | 课件元数据与预览 |
| AI Orchestrator | chem / analytic / image 路由 |
| Sub2API Client | OpenAI 兼容 chat/vision |
| Molecule Extender | 缺分子自动扩展 |
| Quota | 日配额 |

## 4. 部署架构

### 4.1 进程

| 进程 | 命令 | 说明 |
|------|------|------|
| API | `node server/index.js` | HTTP 服务 |
| Worker | `node server/workers/lessonWorker.js` | 异步生成 |
| 前端静态 | Vite build 产物由 API 同域托管（可选） | `dist/` |

### 4.2 存储

| 存储 | 用途 |
|------|------|
| MySQL 或 memory-db.json | 业务数据 |
| `server/uploads/lessons/` | 课件 HTML |
| `server/uploads/ai-images/` | 图片草稿原图 |
| `server/data/molecule-extensions.json` | 分子扩展库 |

### 4.3 外部依赖

- sub2api：`SUB2API_BASE_URL` + `SUB2API_API_KEY` + model
- Python3 + sympy（解几/立几）
- Node ≥ 20

## 5. 核心业务流程（概要）

### 5.1 固定题型

```text
用户选题型 → POST /api/jobs → queued
Worker claim → runGenerate(skill,key) → lesson.html
→ createLesson → job succeeded
```

### 5.2 AI 文本/方程

```text
POST /api/ai/jobs (扣配额)
 → kind=ai
 → Worker:
    chem? runChemAiPipeline
    analytic? runAnalyticAiPipeline
 → known registry 或 LLM Spec → validate → render
 → lesson
```

### 5.3 AI 图片

```text
POST /api/ai/image-drafts (识图，不计生成配额)
 → pending_confirm
用户编辑 editable
 → POST .../confirm (扣配额，创建 AI job, inputMode=image)
 → 走对应学科管线
```

### 5.4 分子扩展（化学）

```text
Spec 含未知 species
 → LLM 生成分子几何 JSON
 → selfcheck
 → 写入 molecule-extensions.json
 → 注入 Python molecules 后再 assemble/render
```

## 6. 技术选型

| 类别 | 选型 | 理由 |
|------|------|------|
| 前端 | React 19 + Vite | 现有工程 |
| 后端 | Express (ESM) | 轻量 API |
| 异步 | 同仓库 Worker 轮询 | 部署简单 |
| 计算 | Python + sympy + skill kernel | 与 edulab 同源正确性 |
| LLM | sub2api OpenAI Compatible | 统一代理 |
| 数据 | MySQL / JSON file | 开发与生产双模 |

---

## 7. 安全设计概要

1. 会话 Token 存服务端 sessions 表/内存。  
2. 密码哈希存储（`password_hash`）。  
3. 角色中间件 `auth` + `requireRole`。  
4. 接口级 rateLimit。  
5. LLM Key 仅环境变量。  
6. 图片大小限制；不执行 LLM 返回代码。  
7. 预览 URL 可带签名过期（preview signing）。

## 8. 可用性与弹性

| 点 | 策略 |
|----|------|
| 上游 429/5xx | 客户端有限重试 + job 修复循环 |
| 模型不可用 | 配置可切换 `SUB2API_MODEL` |
| Worker 崩溃 | lease/stale job 回收 |
| 校验失败 | validation_trace 回传，支持 repair |

## 9. 质量属性设计

### 9.1 正确性

- 化学：`reaction_kernel.assemble_data`
- 解几：analytic schema + template 注入
- 分子：static check + python selfcheck

### 9.2 可扩展

- 新学科：新增 `services/ai/<domain>/pipeline.js` + worker 路由
- 新固定题：skill registry + skillCatalog
- 新模型：只改环境变量

### 9.3 可观测

- worker 控制台日志
- job.progress / current_stage
- ai_meta.usage / attempts
- validation_trace

---

## 10. 模块边界与依赖规则

1. `index.js` 只做 HTTP 编排，不写渲染细节。  
2. pipeline 不直接碰 HTTP request。  
3. LLM client 不包含业务 prompt 细节（prompt 在各学科模块）。  
4. 不长期改 `node_modules` skill 源码；扩展走旁路 JSON/工具脚本。  
5. DB 层屏蔽 MySQL/Memory 差异。

## 12. 风险与对策（概要）

| 风险 | 对策 |
|------|------|
| 上游模型列表变化 | 健康检查 + 可配模型 |
| LLM Spec 不稳定 | schema/kernel 校验 + 重试 |
| 识图不准 | 强制确认门闩 |
| 长耗时 | 异步 job + 长 timeout |
| 成本 | 快路径优先、配额、日限额 |
