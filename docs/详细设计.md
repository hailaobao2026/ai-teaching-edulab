## 3. 运行时组件设计

### 3.1 API Server

- 框架：Express ESM
- 中间件：
  - `auth(required)`：Bearer token → session → user
  - `requireRole(...roles)`
  - `rateLimit(bucket, max, windowMs)`
- 静态托管：存在 `dist/` 时同域托管前端

### 3.2 Worker

文件：`server/workers/lessonWorker.js`

主循环：

1. `initDb` + 回收 stale jobs  
2. 按并发 `claimQueuedJob`  
3. `kind==='ai'` → `processAiJob`，否则 `processJob`  
4. 进度写回 `updateJobProgress`  
5. 成功 `completeJob` + `createLesson`；失败 `failJob`

AI 路由：

```text
infer skillHint(if empty, from source text)
if chem → runChemAiPipeline
else if analytic → runAnalyticAiPipeline
else fail with unsupported route (solid pending M4b)
```

### 3.3 Skill Runner

`skillRunner.runGenerate({ skillId, problemKey, params, outputPath, pythonBin })`

调用对应 skill `scripts/generate.py`，输出 HTML 到 job 工作目录。

### 5.4 AI

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/api/ai/quota` | 是 | 配额 |
| GET | `/api/ai/health` | teacher/admin | sub2api 健康 |
| POST | `/api/ai/jobs` | 是 | 文本/方程 AI 生成 |
| POST | `/api/ai/image-drafts` | 是 | 创建识图草稿 |
| GET | `/api/ai/image-drafts/:id` | 是 | 查草稿 |
| PATCH | `/api/ai/image-drafts/:id` | 是 | 编辑草稿 |
| POST | `/api/ai/image-drafts/:id/confirm` | 是 | 确认并创建 job |
| POST | `/api/ai/image-drafts/:id/discard` | 是 | 丢弃 |

#### POST `/api/ai/jobs`

```json
{
  "inputMode": "text",
  "content": "请演示电解水",
  "skillHint": "edu-chem-reaction",
  "idempotencyKey": "optional-key",
  "options": { "title": "电解水" }
}
```

响应 `202`（首次创建）；相同用户和 `idempotencyKey` 重复提交时返回 `200` 并带 `reused: true`：

```json
{ "job": { "id": "job_...", "status": "queued", "kind": "ai" }, "reused": false, "quota": { "used": 1, "limit": 10, "remaining": 9 } }
```

#### POST `/api/ai/image-drafts`

支持 `multipart/form-data`（字段 `file`，可选 `skillHint`、`note`），也兼容 JSON 图片输入：

```json
{
  "skillHint": "edu-analytic-geometry",
  "note": "可选备注",
  "imageBase64": "data:image/png;base64,...",
  "imageUrl": "https://...",
  "mimeType": "image/png"
}
```

图片必须提供文件、Base64 或 URL；服务端限制 5MB，校验 MIME 与文件头并持久化 `assetPath`，不提供无图的 `skipVision` 调试旁路。Multer 超限返回 `413`，其他上传字段错误返回 `400`。

响应 `201`：`draft` + `recognitionMeta`

#### POST confirm

```json
{ "editable": { "skillId": "edu-chem-reaction", "problemText": "...", "equation": "...", "conditions": "", "ask": "" } }
```

响应 `202`（首次确认）或 `200`（幂等复用）：`{ job, reused, quota, draft }`

## 7. AI 管线详细设计

### 7.1 化学 `runChemAiPipeline`（M1/M2）

路径：`server/services/ai/chem/pipeline.js`

```text
1. 读取 sourceText；Worker 将 AI 阶段统一写为 `routing/generating_spec/validating/repairing/extending_molecules/rendering/persisting`
2. matchKnownChemReaction → 命中则 runGenerate(fixed key)
3. 否则 LLM generateChemSpecFromLlm
4. missingSpecies?
     yes → ensureSpeciesForSpec (LLM分子 + selfcheck + persist)
5. validateChemSpec (chem_spec_tool.py validate [--extensions])
6. 失败则带 error 重试（maxRepairAttempts）
7. renderChemSpec → HTML
8. 返回 spec/validationTrace/moleculeExtensions/aiMeta
```

**ai_meta.pipeline**：`m1_chem` / 扩展后实际写 `m2_chem`  
**route**：`known_registry` | `llm_spec`

#### 分子扩展算法

```text
for species in missing:
  candidate = LLM molecule JSON
  staticCheck (元素/slot/bond)
  python selfcheck-molecule
  if ok: upsert molecule-extensions.json
  else repair loop
```

Python 侧通过 monkey-patch `molecules._LIBRARY_BUILDERS` 注入扩展。

### 7.2 解析几何 `runAnalyticAiPipeline`（M3）

路径：`server/services/ai/analytic/pipeline.js`

```text
1. matchKnownAnalyticProblem（6 keys）
2. 命中 → runGenerate(registry)
3. 否则 LLM → normalizeAnalyticSpec
4. analytic_spec_tool.py validate
5. render → board.html 注入 __LESSON_DATA__
```

**ai_meta.pipeline**：`m3_analytic`

Spec 三段：`lesson` / `steps` / `board`（详见 planning Spec 字段表）

### 7.3 图片识别（M4）

路径：`server/services/ai/image/recognize.js`

```text
输入 multipart file、imageBase64 或 imageUrl
 → visionCompletions (或降级 note chat)
 → JSON normalizeRecognition
 → editable + confidence + warnings
 → saveImageAsset（Base64/multipart 输入）并写回 draft.assetPath
确认后 buildConfirmSourceText → 创建 AI job(inputMode=image)
```

**ai_meta.pipeline**（confirm）：`m4_image`

### 7.4 LLM 客户端

`server/services/llm/sub2apiClient.js`

- `getSub2ApiConfig`（nullish 合并，允许显式空覆盖）
- `chatCompletions`
- `visionCompletions`（image_url content parts）
- `listModels` / `healthCheck`
- 错误分类：`UPSTREAM_WAF|AUTH|RATE_LIMIT|5XX|HTTP|TIMEOUT...`
- 默认 UA：`OpenAI/JS 4.73.0`（可用 `SUB2API_USER_AGENT` 覆盖）
- 请求取消后不再继续传输重试（`SUB2API_ABORTED`）

## 9. 配额设计

`server/services/ai/quota.js` + `db.createAiJob`

- 维度：`user_id + usage_date(YYYY-MM-DD)`
- 字段：`ai_jobs_created`
- limit 来源：角色默认或 system_config / env
- 超额：`QUOTA_EXCEEDED`
- Memory 模式使用文件锁；MySQL 模式使用事务和行锁，配额成功预占与 Job 入库绑定
- 幂等键由 `(user_id, idempotency_key)` 唯一索引保证；复用 Job 不重复计数

## 12. 前端交互要点（与后端契约）

1. 生成中心分固定题型 / AI 生成。  
2. AI 输入切换 text / equation / image。  
3. image：上传 → 展示 editable 确认页 → confirm。  
4. 任务中心轮询 `/api/jobs/:id` 展示 stage。  
5. 失败展示 `error_message` + 可选 validationTrace。  
6. 顶栏/侧栏展示配额 remaining。

## 14. 安全细化

1. 所有 LLM/Vision 调用仅 worker/API 服务端。  
2. 用户输入作为 prompt 数据，不拼接可执行代码；LLM 生成 HTML 经过白名单净化。
3. 分子定义仅 JSON 数据，不 eval。  
4. 管理接口强制 admin。  
5. 公开课件需 publish/visibility 约束。
